### The design question: who does the MCP act as?
IDEA.md's demo step 9 needs a Play made in Claude Code to appear **on the
phone**, so the MCP must act as the phone's user. Reusing the app's Supabase
session (copying a refresh token) was rejected: it rotates and would hand a
harness the app's full powers. Instead:

- **Harness tokens** (`bl_…`): minted in the app, shown once, only a SHA-256
  stored (`harness_tokens`, RLS with no policy). One per user; minting again
  or Disconnect revokes it.
- **Default deny in the engine:** a harness token opens only routes marked
  `config: { harness: true }`, and gets 403 everywhere else. Ghost Plays
  only, **never approve**: the person holding the phone approves. Decided
  without asking, in line with hard rules 1–2; flagged to the user.
- **Anonymous fallback:** with no token, the MCP signs in anonymously with
  the public key, so judges can try it without the app (Ease of reuse).

## Session 2: SpacetimeDB core on an isolated branch

The team chose to enter the SpacetimeDB challenge as well. The user asked for
SpacetimeDB to be central to Baseland's real-time behaviour, with commits on a
new branch and no change to `main`. Branch `feature/spacetime-core` adds a
TypeScript module where Plays and Tape are private owner-scoped state,
reducers apply transactional updates, and a public projection broadcasts
safe Ghost activity. The engine uses that module as its authoritative Play
store. The iPhone receives only the signed-in user's updates through an
authenticated engine event stream; the public Arena subscribes directly to
SpacetimeDB. Supabase remains Auth, Rig/Deck and credential storage.

### Why the boundary is this way

The engine still owns market watching, the Brain, Leash, and Coinbase
gateway, so SpacetimeDB can give shared transactional state without exposing
keys or private Tape payloads to Arena clients. The projection contains only
Ghost summaries. Live trading remains off in local testing. A migration
script counts and guards the Supabase source before any import; its dry run
found zero Plays and Tape rows at the end, so nothing was imported. The
existing Render engine still runs `main`; its environment and data cutover
must be coordinated before this branch could become the deployed engine.
