## Session 1: ideation and planning (no code)

### The brief
The Coinbase sponsor PDF ("CalHacks: Build agents that trade and pay") has two
tracks: Payment Agents and Trading Agents. We chose **Trading Agents** as the
primary track, with x402 as a secondary. It is judged on usefulness,
technical design, ease of reuse, and product feedback, and explicitly *not*
on code volume, returns, or money spent. Simulated actions must be labeled,
credentials kept private, and no funds managed for other people. Full list in
`submission-checklist.md`.

### Research that shaped the idea
- **Coinbase for Agents** (June 2026; stocks and x402 added September;
  "open for AI agents" announced 2026-10-22): an MCP and CLI for trading
  900+ crypto pairs, US equities, futures, portfolios, and x402 via a curated
  catalog (Arkham, Drip, Exa, Glassnode, Massive, Nansen, You.com). Remote MCP
  OAuth works only in allowlisted harnesses.
- **Coinbase Advisor** (June 2026): an SEC-registered AI advisor that cannot
  trade.
- **Coinbase plans** max trade sizes and spending caps, so those are not our
  headline.
- **Robinhood (HOOD Summit 2026):** in-app Agents with model choice, a
  dedicated account, approvals on by default, "Loops" coming soon, and
  Agent Apps as $5–30/month data subscriptions.
- **Public:** AI Agents built by chat, with event triggers (CPI, earnings),
  approval of rules at setup, and a marketplace.
- **Tradetron:** shows P&L in the Dynamic Island but cannot approve trades.
  We found no app that approves an agent's trade from the Island.

### Decision: Plays
Event-scoped missions living in a Live Activity; a Deck of swipeable cards
plus chip-sentences instead of chat; approval from the Island; x402 evidence
per decision with receipts; Ghost mode; and the Rig (Brain / Senses /
Instincts / Hands / Leash, Replay, Cartridges, Tape, Account). Rejected as
the core idea: Thesis Garden, Second Look, and a portfolio-as-map UI (all in
`feature-backlog.md` or `IDEA.md` §9).

### Coinbase key: sandbox rejected, production key used unfunded
The first key was a sandbox key. `api-sandbox.coinbase.com` returned canned
balances **even for a randomly generated key**, had no product data and no
x402, so it validates nothing. The user created a production key scoped to an
empty `baseland` portfolio (no funds until Phase 4, at the user's request,
and Ghost by default). Verified read-only: it reaches `baseland` and is
**denied** on Default. `balance` rejects the scoped portfolio even with its
uuid (it may just be empty); `portfolios get` works. All of this is in
`builder-feedback.md`.

### What was built and verified
- **Repo** `github.com/adylagad/baseland` (public), committed as `adylagad`.
- **Schema** (Supabase `vxapuqgqvecokhmfmnjl`): profiles, credentials, plays,
  tape, deck_cards. Clients read only (owner RLS); the engine writes;
  `credentials` has no policy. The advisor flagged our trigger functions as
  RPC-callable, which a follow-up migration revoked (verified).
  `rls_auto_enable` is Supabase's own function and was left alone.
- **Engine** (Fastify, TS): `/health`, `/v1/market/:id` (public Coinbase
  API, no key), and `/v1/credentials` (connect / status / forget). The CLI
  runs per call with the key only in that child's env plus a throwaway config
  dir. A key is accepted only if it reaches exactly one portfolio that is not
  Default. Secrets are stored AES-256-GCM encrypted. 18 vitest tests.
  **End to end, locally and on Render:** anonymous sign-in, real key
  connected as `baseland`, ciphertext in the DB, a client reads `[]` from
  credentials, and no key material in logs. The test users were deleted
  afterwards, since each held an encrypted copy of the key.
- **Deployed** at `https://baseland-engine.onrender.com` (free, Docker).
  Secrets were set through Render's REST API from the shell, reading `.env`,
  so their values never passed through the chat. The first deploy crashed by
  design (config validation named the missing secrets) because it started
  before they were set.
- **Keep-alive:** a Supabase `pg_cron` + `pg_net` job pings `/health` every
  5 minutes. That replaced the cron-job.org plan, so the user needs no extra
  account. It was verified waking a cold instance.
- **iOS:** XcodeGen project, `BaselandKit` (stage model, Live Activity
  attributes, Theme tokens, Island views), widget extension, and an Island
  Lab dev screen. **Seen in the real simulator Dynamic Island** (iPhone 17,
  iOS 26.5) in watching, deciding, awaiting and done, updating with another
  app in front. 5 Swift Testing tests.

### Problems hit (each recorded where it belongs)

  the controller now holds only its id (code trap).
- The compact countdown truncated at 52pt; it now has a fixed 58pt width
  (code trap).
- **SwiftPM's `.build/` index (2,277 files) got committed.** The push was
  killed before it landed (the remote was verified unchanged), and the commit
  was amended and `.build/` gitignored (code trap).
- **Pushes don't trigger Render deploys**: the GitHub app is presumably not

  backlog).
- The feature-ledger entry for the engine went in a separate commit instead

  than rewritten).
